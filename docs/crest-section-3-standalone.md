# THE CREST: Section 3, the standalone PWA

This supersedes the Section 3 line in `docs/crest-cursor-build-brief.md`. The Crest ships as its own app, not a route inside thereflectivefootball.com.

---

## THE ARCHITECTURE DECISION

| Layer | Where it lives | Why |
|---|---|---|
| `crest_clubs` table, seed, enrichment script | Stays in `trf-project` | Already built in Sections 1 and 2. It is data tooling, not UI, and it belongs next to the other Supabase work. |
| The app | New repo, `crest-app` | Own Vercel project, own domain, own manifest and icon. This is what makes it installable as its own thing. |
| Club data at runtime | Baked into the bundle as `public/clubs.json` at build time | The app works with no network, no database and no API key. Club culture changes yearly, not hourly. |
| Sportmonks | Never called by the app | Enrichment happens in `trf-project`, lands in Supabase, and reaches the app through the build-time snapshot. |

Nothing in the app touches a secret, so the whole thing can be static and offline.

Suggested domain: `crest.thereflectivefootball.com`, which keeps the TRF association without burying it in the site.

## SECTION 3 PROMPT

Paste into Cursor in Agent mode, in a new empty repo called `crest-app`.

```
Build Section 3 only, then stop.

Goal: a standalone, installable, offline-first PWA. Flow only. No scoring engine,
no result screen. Those are Section 4.

1. Next.js App Router, static export (output: 'export'). No server runtime.
   Deployed as its own Vercel project. Do not add Supabase, Sportmonks or any
   API client to this repo.

2. Data snapshot:
   - scripts/snapshot-clubs.mjs reads crest_clubs from Supabase using the service
     role from .env.local, and writes public/clubs.json.
   - It runs manually, not on every build, and the output is committed.
   - It writes only the fields the app needs: slug, name, city, country, cluster,
     vector, confidence, identity_summary, exclusion_clubs, badge_url,
     archetype, uae, trf_film_youtube_id, research_status.
   - If clubs.json is missing at build time, the build fails with a clear message
     rather than shipping an empty app.

3. PWA:
   - manifest.webmanifest: name "The Crest", display standalone, portrait,
     background #F2EDE4, theme #0A111F.
   - Icons at 192, 512 and maskable 512, generated by scripts/make-icons.mjs from
     a single source SVG in assets/, using sharp. Commit the generated PNGs.
   - Service worker precaches the shell, clubs.json, the fonts and the icons, so a
     second visit works in airplane mode. Cache name includes a version string.
   - iOS: apple-mobile-web-app-capable, status bar style, and an apple-touch-icon,
     because iOS ignores the manifest icons.
   - An install prompt appears once, after the user finishes their first result,
     never on the opening screen.

4. The flow, ported from docs/crest-prototype.html. Rebuild it as components, do
   not paste the HTML in:
   - Opening screen
   - "Do you already have a club" grid, multi-select, plus a "No club yet" option
   - Twelve question screens, one per dimension, five tap options each, mapped to
     1, 2.5, 4, 5.5 and 7
   - The pillar weighting question, last
   - A twelve-tick progress rail, and a back control on every screen

5. State lives in a single reducer, persisted to localStorage on every answer, so
   closing the app mid-quiz resumes where the user left off. Clear it on restart.

6. Layout:
   - Phone first. Options are thumb-reachable and at least 56px tall.
   - Tablet at 760px and up: options in two columns, question and options share
     the screen rather than stacking to a long scroll.
   - Respect safe-area insets, since standalone mode has no browser chrome.
   - prefers-reduced-motion respected. Visible keyboard focus on every control.

7. Brand: cream #F2EDE4, navy #0A111F, signal red #D8232A, Bodoni Moda display,
   Archivo UI. Self-host the two fonts in the repo rather than loading from
   Google, because the app must work offline on first launch after install.

8. No em-dashes in any copy. Sentence case. Every screen has a way back.

Then stop and report: the Lighthouse PWA score, the total bundle size, and
whether it installs cleanly on iOS Safari and Android Chrome.
```

## WHAT SECTION 4 WILL ADD

Scoring engine, exclusions, diversification, percentile display, the live crest SVG and the result screen. All client side, all offline, because the club set is already in the bundle.

## WHAT STAYS IN TRF-PROJECT

`/crest` on the main site becomes a short landing page pointing at the app, so the site keeps its no dead ends rule without duplicating the product. That is a later section, and it is small.
